# HH Telegram Manager — Roadmap

Проект уже умеет:

- авторизовывать пользователя в HH;
- выходить из аккаунта;
- запускать автоотклик;
- запускать автоподнятие резюме;
- показывать статистику;
- редактировать сопроводительное письмо;
- управлять `hh-applicant-tool` через Telegram.

Дальше развиваем не “бот с нуля”, а стабильный личный инструмент для 1–2 пользователей.

---

# Главный приоритет

Сейчас важнее всего:

1. закрыть технические дыры, которые могут привести к дублям/ошибкам;
2. не перегружать интерфейс техническими логами;
3. быстрее перейти к AI-функциям;
4. не добавлять то, что не нужно для маленького личного использования.

---

# Sprint 1 — Lifecycle Safety

Цель: сделать запуск и остановку надёжными.

## 1. Lock от двойного запуска

Проблема:

Пользователь может быстро нажать кнопку запуска несколько раз.

Риск:

- несколько контейнеров;
- дубли откликов;
- конфликт статистики;
- странное состояние UI.

Что сделать:

- добавить lock на пользователя и действие;
- не разрешать повторный запуск, пока текущий процесс стартует или работает;
- lock должен сниматься после успешного старта, ошибки или остановки.

Пример ключа:

```text
automation_lock:<telegram_user_id>
```

Статус: обязательно.

2. Расширенные статусы процесса

Нужны статусы:

starting
running
stopping
stopped
failed

Что это решает:

UI не врёт пользователю;
кнопка запуска/остановки меняется корректно;
проще диагностировать ошибки;
проще потом добавить AI-запуски и dry-run.

Статус: обязательно.

3. Docker diagnostics

Нужно отличать состояния контейнера:

не запускался;
запускается;
работает;
завершился успешно;
остановлен пользователем;
упал с ошибкой.

Что использовать:

docker ps;
docker ps -a;
exit code;
container status;
last error.

Пользователю не показывать сырые Docker-ошибки по умолчанию.

Статус: обязательно.

Sprint 2 — Minimal User Diagnostics

Цель: дать пользователю понять, что произошло, но не превращать бота в консоль логов.

4. Кнопка “Последние события”

Не делать полноценный live-log.

Кнопка:

🧾 Последние события

Что показывать:

запуск начался;
автоподнятие выполнено;
автоотклики запущены;
сколько откликов отправлено;
сколько вакансий пропущено;
была ли ошибка.

Если парсинга событий пока нет, можно временно показывать последние 30–50 очищенных строк логов.

Статус: желательно.

5. Санитизация логов/событий

Перед любым выводом пользователю нужно вырезать:

токены;
SMS-коды;
телефоны;
email;
access_token;
refresh_token;
Authorization headers.

Статус: обязательно, если показываем события/логи.

Sprint 3 — AI v1 через возможности hh-applicant-tool

Цель: быстро добавить AI без написания собственного AI-движка.

6. AI-настройки

Добавить простой экран настроек:

AI-фильтр: выключен / light / heavy
AI-сопроводительные: выключены / включены

Пока без сложных промптов и без своей AI-архитектуры.

Статус: обязательно перед AI-запусками.

7. AI dry-run

Это первая AI-фича.

Кнопка:

🧪 AI-тест

Что делает:

запускает apply-vacancies с --dry-run;
использует выбранный --ai-filter light/heavy;
реальные отклики не отправляет;
показывает короткий итог.

Пример:

AI-тест завершён.

Найдено вакансий: 30
AI одобрил: 14
AI отклонил: 16
Реальных откликов: 0

Статус: обязательно перед боевым AI.

8. Боевой запуск с AI-фильтром

После AI dry-run добавить запуск автооткликов с AI-фильтром.

Режимы:

Обычный запуск
Запуск с AI-фильтром

На старте лучше использовать light.

heavy оставить как более осторожный/дорогой режим.

Статус: после AI dry-run.

9. AI-сопроводительные

Добавить переключатель:

AI-сопроводительные: включены / выключены

Если выключены:

используется текущий редактор сопроводительного.

Если включены:

hh-applicant-tool использует встроенную AI-генерацию.

Статус: после AI-фильтра.

Sprint 4 — UX для обычного пользователя

Цель: сделать AI понятным не разработчику.

10. Предупреждение перед первым AI-запуском

Перед первым боевым AI-запуском показать:

AI может ошибаться и отклонять хорошие вакансии.
Сначала рекомендуется запустить AI-тест.

Статус: желательно.

11. Простые объяснения режимов

В настройках AI добавить короткие подсказки:

light — быстрее, анализирует базовые данные вакансии.
heavy — медленнее, анализирует подробнее.

Статус: желательно.

Sprint 5 — AI v2 через custom operations

Цель: перейти от встроенного AI к своим сценариям, когда встроенных возможностей станет мало.

12. Собственная operation в hh-applicant-tool

Добавить свою команду внутри hh-applicant-tool, например:

smart-apply-preview

или:

ai-vacancy-preview

Задача:

получить список вакансий;
прогнать через свой AI-слой;
вернуть структурированный результат;
не отправлять отклики.

Статус: позже.

13. AI-анализ вакансии

Кнопка:

🧠 AI-анализ

Ответ:

Score: 78/100
Вердикт: можно откликаться

Плюсы:
- Vue/Nuxt
- удалёнка
- продуктовая команда

Минусы:
- не указана зарплата
- возможно legacy

Статус: после перехода к custom operations.

14. AI-генерация письма с ручным подтверждением

Кнопка:

✍️ Сгенерировать письмо

Flow:

AI генерирует письмо.
Пользователь видит текст.
Пользователь нажимает:
сохранить;
перегенерировать;
отменить.

Статус: после custom operations.

Что пока НЕ делаем

Чтобы не раздуть проект, пока не добавляем:

live logs;
heartbeat;
автоперезапуск после падения;
сложный crash recovery;
web dashboard;
сложные роли пользователей;
полноценную CRM;
локальную Qwen/Ollama-инфру;
AI-ответы работодателям;
AI captcha;
сложный ranking;
антиспам на базе AI;
редактирование промптов из Telegram;
multi-account UI, если текущих 1–2 пользователей хватает без него.
Итоговый порядок
1. Lock от двойного запуска
2. Статусы starting/running/stopping/stopped/failed
3. Docker diagnostics
4. Последние события + sanitization
5. AI-настройки
6. AI dry-run
7. Боевой AI-фильтр
8. AI-сопроводительные
9. UX-подсказки для AI
10. Custom operations для собственного AI
Ближайшая цель

Сделать так, чтобы пользователь мог безопасно пользоваться ботом так:

1. Запустить обычный автоотклик.
2. Видеть честный статус.
3. Не запустить дубль случайным двойным нажатием.
4. Посмотреть короткие последние события.
5. Запустить AI-тест без реальных откликов.
6. После этого включить AI-фильтр в боевом режиме.
