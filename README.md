# hh-telegram-bot

Telegram-бот-пульт для управления внешним `hh-applicant-tool`.

Бот не реализует HH-логику сам. Он только проводит пользователя через сценарий авторизации и запускает или останавливает заранее разрешенный Docker Compose сценарий в каталоге `HH_TOOL_WORKDIR`.

## Возможности MVP

- доступ только для Telegram ID из `TELEGRAM_ALLOWED_USER_IDS`;
- `/start` или любое сообщение для открытия бота;
- отдельный профиль `hh-applicant-tool` для каждого разрешённого Telegram-пользователя;
- проверка текущей авторизации в `hh-applicant-tool` при `/start`;
- краткая сводка по аккаунту после успешной проверки авторизации;
- авторизация по телефону и SMS-коду через `hh-applicant-tool authorize`;
- личный кабинет с inline-кнопками:
  - `▶️ Запустить`, если сценарий не запущен;
  - `⏹ Остановить`, если сценарий запущен;
- отдельная кнопка `📊 Статистика` в личном кабинете;
- кнопка `✉️ Сопроводительное письмо` для просмотра и изменения личного письма;
- кнопка `🧠 AI тест` для проверки связи с локальной OpenAI-compatible моделью;
- кнопка `🧪 AI-анализ` для dry-run проверки AI-фильтра в `hh-applicant-tool`;
- кнопка `🔴 Выйти` для выхода из HH-аккаунта и последующего входа под другим номером;
- запуск автоотклика по поисковому запросу, который пользователь вводит сам;
- предпросмотр перед запуском: сколько вакансий HH нашёл по запросу и сколько бот максимум проверит;
- запуск персонального контейнера автоматизации через Docker Compose;
- остановка персонального контейнера автоматизации;
- проверка статуса персонального контейнера;
- живое сообщение со статистикой запущенной автоматизации и кнопкой `⏹ Остановить`.

## Ограничение авторизации

Авторизация через Telegram запускает штатную команду `hh-applicant-tool authorize <phone>` в Docker Compose и передаёт SMS-код в stdin этого процесса.

Бот не считает введённый SMS-код успешной авторизацией сам по себе. Успех подтверждается только реальной проверкой аккаунта через `hh-applicant-tool`.

Для каждого Telegram-пользователя используется отдельный `HH_PROFILE_ID` вида `tg_<telegram_user_id>`. Это значит, что токены, cookies, резюме в локальной базе и статистика не смешиваются между пользователями.

Если HH попросит капчу, бот отправит картинку в Telegram, примет ответ и продолжит тот же процесс входа.

## Сопроводительное письмо

В личном кабинете есть кнопка `✉️ Сопроводительное письмо`.

В этом разделе можно:

- посмотреть текущий текст;
- изменить текст;
- вернуться в главное меню.

Письмо хранится отдельно для каждого Telegram-пользователя в профиле `hh-applicant-tool`: `config/tg_<telegram_user_id>/letter.txt`.

При запуске автоматизации бот передаёт этот файл в `hh-applicant-tool apply-vacancies` через параметр `-L`. Если письмо ещё не задано, общий `/app/letter.txt` не используется, а `hh-applicant-tool` работает со своим стандартным текстом.

Автоматизация запускается в персональном Docker-контейнере пользователя. Внутри контейнера бот выполняет только заранее заданную цепочку команд: обновление токена, поднятие резюме и отклики на вакансии. Произвольные команды из Telegram не принимаются.

## Запуск автоотклика

После нажатия `▶️ Запустить` бот просит выбрать режим, затем предлагает ввести поисковый запрос для HH. Этот запрос передаётся в `hh-applicant-tool apply-vacancies --search`.

Бот запоминает последние поисковые запросы в профиле пользователя и при следующем запуске показывает их кнопками. Можно выбрать старый запрос или отправить новый текстом.

Перед реальными откликами бот проверяет выдачу через безопасный вызов `hh-applicant-tool call-api /vacancies` и показывает:

- сколько вакансий HH нашёл по запросу;
- сколько вакансий реально доступно к проходу через HH API;
- сколько вакансий бот максимум проверит с выбранным лимитом;
- технический лимит прохода для режима `Все доступные`.

Отклики начинаются только после подтверждения на экране предпросмотра.

После завершения запуска бот показывает краткий итог: время работы, запрос, найдено/доступно/обработано, отправленные отклики, тесты и основные причины пропуска вакансий.

## Статистика запущенной автоматизации

После нажатия `▶️ Запустить` бот отправляет сообщение:

```text
🟢 Авто-отклик бот запущен

📨 Сессия
• Откликов отправлено: 0
• Тестов выполнено: 0

📬 HH
• Отказов: 0
• Приглашений: 0
```

Это сообщение редактируется, когда статистика меняется. Во время запущенной автоматизации под сообщением остаётся только кнопка `⏹ Остановить`.

Telegram не позволяет задавать inline-кнопкам цвет или стиль `danger`, поэтому кнопка остановки выделена текстом и символом остановки.

Отклики и выполненные тесты за сессию считаются по логам персонального контейнера. Отказы и приглашения берутся из локальной базы профиля `hh-applicant-tool`, если эти данные уже синхронизированы утилитой.

Кнопка `📊 Статистика` показывает отклики, отказы, приглашения и выполненные тесты за сегодня, 7 дней и 30 дней. Отклики, отказы и приглашения считаются по локальной базе профиля. Выполненные тесты считаются по логам текущего персонального контейнера.

Карточка личного кабинета кэшируется в профиле `hh-applicant-tool`, чтобы открываться быстро без Docker-запроса на каждый показ.

Бот старается держать один активный экран: при переходах между личным кабинетом, статистикой, сопроводительным письмом и подтверждением выхода старый экран удаляется. После успешной авторизации бот также удаляет сообщения текущего сценария входа, которые он видел и которые Telegram разрешает удалить.

## Установка

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## Настройка

Создайте `.env` по примеру:

```powershell
Copy-Item .env.example .env
```

Заполните:

```dotenv
TELEGRAM_BOT_TOKEN=123456:replace-me
TELEGRAM_ALLOWED_USER_IDS=123456789,987654321
HH_TOOL_WORKDIR=C:\projects\hh-applicant-tool
AI_ENABLED=true
AI_PROVIDER=ollama
AI_BASE_URL=http://localhost:11434/v1
AI_MODEL=qwen2.5:3b
AI_API_KEY=ollama
```

`HH_TOOL_WORKDIR` должен указывать на каталог, где находится Docker Compose конфигурация `hh-applicant-tool`.

AI-настройки нужны для кнопок `🧠 AI тест` и `🧪 AI-анализ`. Если AI пока не нужен, укажите `AI_ENABLED=false` или не добавляйте AI-переменные в `.env`.

## Локальный AI через Ollama

Бот умеет проверить связь с локальной моделью через OpenAI-compatible endpoint Ollama и запустить безопасный AI dry-run через `hh-applicant-tool`. Боевой AI-автоотклик пока не включен.

1. Установите Ollama с официального сайта: https://ollama.com

2. Скачайте модель:

```powershell
ollama pull qwen2.5:3b
```

3. Убедитесь, что Ollama запущена и доступна по адресу:

```text
http://localhost:11434/v1
```

4. Добавьте в `.env`:

```dotenv
AI_ENABLED=true
AI_PROVIDER=ollama
AI_BASE_URL=http://localhost:11434/v1
AI_MODEL=qwen2.5:3b
AI_API_KEY=ollama
```

`AI_API_KEY=ollama` используется как техническая заглушка для OpenAI-compatible клиента.

5. Запустите бота и нажмите в личном кабинете кнопку `🧠 AI тест`.

Бот отправит безопасный prompt:

```text
Ответь коротко: локальная модель подключена и работает.
```

Если Ollama не запущена, модель не скачана или endpoint не отвечает, бот покажет короткое сообщение об ошибке без внутренних путей и stack trace.

6. Для проверки реального пути через `hh-applicant-tool` нажмите `🧪 AI-анализ`, выберите режим `Light` или `Heavy`, затем выберите объём проверки: 10, 30 или 50 вакансий.

Бот запустит безопасный dry-run с выбранным AI-фильтром, будет редактировать одно Telegram-сообщение со статистикой и остановит контейнер, когда модель проверит выбранное число вакансий. Уже отклонённые ранее вакансии показываются отдельным счётчиком и не считаются в прогон.

```text
apply-vacancies --dry-run --ai-filter light|heavy
```

Реальные отклики не отправляются. Перед запуском бот синхронизирует AI-настройки в секцию `openai_vacancy_filter` текущего профиля `hh-applicant-tool`.

Так как `hh-applicant-tool` запускается внутри Docker, адрес `localhost` из `AI_BASE_URL` для dry-run автоматически преобразуется в `host.docker.internal`. Это нужно, чтобы контейнер смог обратиться к Ollama, запущенной на хосте.

## Запуск

```powershell
python -m bot.main
```

После запуска отправьте боту `/start`.

## Безопасность

- бот не принимает произвольные команды из Telegram;
- команды запуска и остановки зафиксированы в коде;
- `shell=True` не используется;
- токен бота и ID пользователей читаются только из `.env`;
- телефон и SMS-код не пишутся в логи;
- внутренние пути и stack trace не отправляются пользователю.
